# Архитектура

Документ описывает, из каких частей состоит система и как они связаны.

## 1. Что строим

**Студенческую соцсеть** в духе VK или Facebook: аккаунт, личный профиль, посты, истории и лента. Одно приложение на iPhone, Android и в браузере, один общий код. Друзья, личные сообщения, группы и новости вуза — позже.

**Анонимные голосовые комнаты — один из разделов (модулей) этой соцсети**, а не весь продукт. Он сделан первым. Остальные модули добавляются по очереди — см. [ROADMAP.md](ROADMAP.md).

## 2. Ядро и модули

```
┌───────────────────────────────── СОЦСЕТЬ ─────────────────────────────────┐
│                                                                            │
│  ЯДРО — нужно всем разделам                                                │
│  ┌──────────┬──────────┬──────────┬──────────┬───────────┬──────────────┐  │
│  │ Вход и   │ Аккаунт  │ Профиль  │ Фото     │ Уведомле- │ Админка      │  │
│  │ пригла-  │ и роли   │ (открытый│ (хране-  │ ния       │ и журнал     │  │
│  │ шения    │          │ )        │ ние)     │           │              │  │
│  │ сделано  │ роли —   │ часть 1  │ часть 1  │ в браузере│ позже        │  │
│  │          │ часть 1  │          │          │           │              │  │
│  └──────────┴──────────┴──────────┴──────────┴───────────┴──────────────┘  │
│        ▲                                                                   │
│        │ «кто этот человек, какая у него роль, не забанен ли»              │
│        │                                                                   │
│  МОДУЛИ — разделы соцсети, не знают друг о друге                           │
│  ┌───────────────┐ ┌────────────┐ ┌─────────┐ ┌─────────┐                  │
│  │ Голосовые     │ │ Посты,     │ │ Лента   │ │ Истории │   позже: друзья, │
│  │ комнаты       │ │ лайки,     │ │         │ │         │   сообщения,     │
│  │ (анонимные,   │ │ комментарии│ │         │ │         │   группы,        │
│  │ только        │ │            │ │         │ │         │   новости        │
│  │ студентам)    │ │            │ │         │ │         │                  │
│  │ сделано       │ │ часть 2    │ │ часть 3 │ │ часть 4 │                  │
│  └───────────────┘ └────────────┘ └─────────┘ └─────────┘                  │
└────────────────────────────────────────────────────────────────────────────┘
```

Правила:

- **Модуль пользуется ядром, ядро о модулях не знает.** Модули не обращаются друг к другу.
- У каждого модуля свои папки кода, свои таблицы и свои адреса запросов (`/v1/<модуль>/...`). Подключение модуля к серверу — одна строка.
- Ядро отвечает модулю на три вопроса: «кто этот человек» (вошёл ли он), «какая у него роль» и «не забанен ли». Больше модулю знать не нужно.
- Лента — тоже модуль, но особый: она ничего не хранит сама, а собирает экран из постов и историй.

## 3. Три личности одного человека

| | Аккаунт | Профиль соцсети | Персона комнат |
|---|---|---|---|
| Что это | почта, вход, роль, баны | открытая страница: имя, аватар, факультет, курс, «о себе», роль, посты | анонимный ник для голосовых комнат |
| Где | ядро | ядро (часть 1) | модуль комнат |
| Кто видит | сервер и админы | все вошедшие пользователи | собеседники в комнате |
| У кого есть | у всех | у всех | только у студентов |
| Идентификатор | `accountId` — наружу не выходит | `profileId` | `personaId` |

Главный принцип комнат: **анонимно для собеседников, но не для модерации.**

## 3а. Роли

У каждого аккаунта одна роль; пока её задаёт тип кода приглашения, поменять может только админ. Роль видна в профиле.

| Что можно | Студент | Преподаватель | Гость |
|---|---|---|---|
| Смотреть ленту, профили, истории; свой профиль | да | да | да |
| Посты, истории, лайки, комментарии | да | да | нет |
| Голосовые комнаты | да | нет | нет |

Как это устроено:

- Права ролей записаны в одном месте общей части кода. Сервер спрашивает его перед каждым действием, приложение — чтобы решить, какие кнопки показывать.
- **Проверяет сервер.** Скрытая кнопка — это удобство, а не защита: ручной запрос в обход приложения получает отказ. На каждый запрет есть автотест.
- Преподаватель и гость не видят кнопку войса и пункт «Войс»; гость не видит «Создать», лайк и поле комментария.

## 4. Как модуль комнат пользуется ядром и не выдаёт человека

```
 Пользователь соцсети (вошёл один раз)
        │  нажимает круглую кнопку
        ▼
 Модуль комнат получает запрос с токеном входа
        │
        ▼
 Ядро: «токен настоящий, это аккаунт №…, роль — студент,   ← аккаунт остаётся внутри сервера
        не забанен»
        │
        ▼
 identity (единственный «мост»): аккаунт → персона комнат   ← таблица persona_links
        │
        ▼
 Модуль комнат дальше работает ТОЛЬКО с персоной:
 выбирает комнату, выдаёт пропуск на сервер звука,
 где человек известен как personaId + ник
```

Чем это обеспечено:

1. Аккаунт, профиль и персона — разные таблицы. Связь аккаунта с персоной лежит в одной таблице `persona_links`; читать её может только один небольшой модуль сервера — `core/identity`. Это проверяет автотест.
2. Профиль привязан к аккаунту, персона — тоже к аккаунту, но через «мост». Напрямую профиль и персона не связаны нигде.
3. Запросы модуля комнат отдают только `personaId` и ник. Запросы ядра и остальных модулей никогда не отдают `personaId` и ник комнат. Данные профиля и персоны не встречаются в одном ответе — даже в ответе самому человеку.
4. Сервер звука (LiveKit) получает только `personaId` и ник; об аккаунтах и профилях он не знает.
5. Автотест проверяет каждый ответ сервера: в нём не должно быть почты и данных аккаунта.
6. Админ может раскрыть связь только через админку, с причиной; каждый просмотр пишется в журнал.

**Косвенные утечки.** Функции соцсети не должны выдавать персону обходным путём: профиль и друзья не видят, что человек сейчас в комнате; лента и уведомления друзьям о комнатах молчат. Остаточные риски (например, друг узнал голос) — в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).

Баны и подсчёт «выгнали из 3 комнат» ведутся по аккаунту — смена ника не помогает.

## 5. Схема системы

```
  iPhone / Android / браузер
  (одно приложение: Expo + React Native + TypeScript)
        │                  │                    │
        │ HTTPS (REST)     │ push               │ WebRTC (звук)
        ▼                  ▼                    ▼
  ┌─────────────────────────────┐        ┌──────────────┐
  │  Наш сервер                 │──────► │   LiveKit    │
  │  Node.js + TypeScript       │        │ (голос, наш  │
  │  ядро + модули              │        │ сервер, без  │
  └──────────────┬──────────────┘        │ записи)      │
                 ▼                       └──────────────┘
            PostgreSQL
```

Всё серверное размещается на российском хостинге.

## 6. Части системы

| Часть | Технология | Состояние |
|---|---|---|
| Приложение | Expo (React Native) + TypeScript, Expo Router | работает в браузере; на телефонах не запускалось |
| Сервер | Node.js + TypeScript, Fastify | работает |
| База данных | PostgreSQL + Drizzle ORM (при разработке — встроенная) | работает |
| Голос | LiveKit на своём сервере, только звук, запись не установлена | работает в браузере |
| Push | Web Push в браузере; на телефонах — позже | в браузере |
| Почта | российский сервис рассылки | не подключена |
| Ошибки | GlitchTip на своём сервере | не подключён |
| Админка | отдельная веб-страница, вход с 2FA | не сделана |
| События в реальном времени | свой WebSocket | понадобится для голосований и сообщений |
| Быстрая память | Redis | понадобится при росте нагрузки |
| Хранилище фото | при разработке — диск компьютера; для запуска — российское облачное хранилище (вопрос D8) | часть 1 |
| Обработка фото | уменьшение и стирание служебных данных (места съёмки) при загрузке | часть 1 |

Нерешённые вопросы по хостингу, почте и push — в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md). Причины выбора — в [DECISIONS.md](DECISIONS.md).

## 7. Структура репозитория

```
apps/
  server/src/
    core/                 ЯДРО: вход, аккаунт, роли, профиль, фото, уведомления, identity («мост»)
    modules/rooms/        МОДУЛЬ комнат: персона, расписание, напоминания, вход в комнату, звук
    modules/posts/        МОДУЛЬ постов (часть 2); дальше — feed/, stories/
    db/schema/            таблицы: core.ts, rooms.ts, bridge.ts
    app.ts                сборка сервера: ядро + модули
  mobile/src/
    lib/, ui/             ЯДРО: запросы, сессия, общие элементы интерфейса
    features/rooms/       МОДУЛЬ комнат: кнопка входа, расписание, звук
    app/                  экраны: общие — в корне, экраны модуля — в app/rooms/
  admin/                  админка (позже)
packages/
  shared/src/
    core/                 общие форматы ядра
    rooms/                общие форматы модуля комнат
infra/                    настройки развёртывания (позже)
docs/                     эта документация
```

Новый модуль — это новая папка в каждом из трёх мест (`modules/<имя>`, `features/<имя>`, `shared/<имя>`), свой файл таблиц и одна строка подключения в `app.ts`.

## 8. Путь пользователя

1. **Один раз:** код приглашения и почта → код из письма → заполнить профиль (имя, аватар, факультет, курс, «о себе»). Роль уже определена типом кода приглашения.
2. **Главный экран:**

```
┌──────────────────────────────┐
│  ◯  ◯  ◯  ◯  ◯   истории     │
├──────────────────────────────┤
│  ( ● )  Анонимный войс       │  ← закреплена всегда; только у студентов
├──────────────────────────────┤
│  пост                        │
│  пост                        │  лента: посты всех, новые сверху,
│  пост …                      │  подгрузка при прокрутке
├──────────────────────────────┤
│ Лента   Войс   Создать  Профиль │  ← «Войс» — только студентам,
└──────────────────────────────┘     «Создать» — не гостям
```

3. **В комнату:** кнопка войса → меню (ближайшие комнаты, «Войти», напоминания) → «Войти» → человек в комнате. При самом первом входе студент один раз придумывает ник комнат.
4. В комнате: входит с выключенным микрофоном, слушает, потом говорит. Собеседники видят только ник. Модерация — голосованием участников ([MODERATION_RULES.md](MODERATION_RULES.md)).
5. После комнаты 24 часа можно тайно отметить «хочу пообщаться ещё»; при взаимной отметке — ступени раскрытия.

## 9. Голос

- LiveKit работает как «ретранслятор»: каждый отправляет звук один раз на сервер, сервер раздаёт остальным. Это выдерживает 25 человек на слабых телефонах.
- Только звук: пропуск на сервер звука разрешает лишь микрофон — ни видео, ни показа экрана, ни произвольных данных.
- Запись звука невозможна технически: компонент записи LiveKit не устанавливается.
- Когда время комнаты вышло, сервер сам закрывает её и отключает всех.
- На iPhone и Android нужна сборка приложения с нативным модулем LiveKit — пока не сделана.

## 10. Безопасность и данные

- Не собираем телефон и фото документов. Имя в профиле — как человек сам написал.
- С каждого загруженного фото стираются служебные данные, в том числе место съёмки.
- Удаление аккаунта удаляет профиль, посты, истории, комментарии, лайки, фото и персону комнат.
- Почта хранится зашифрованной; для поиска при входе — её отпечаток.
- Невзаимные отметки не показываются никому (в том числе в админке) и удаляются после 24 часов.
- Секреты — только в переменных окружения, не в репозитории.
- Нет интеграции с системами вуза. Название и логотип КубГУ не используются до разрешения.

Открытый профиль с именем и фото — это больше персональных данных, чем почта и ник; вопросы к юристу — C8–C12.
