# Архитектура

Документ описывает, из каких частей состоит пилот и как они связаны. Кода пока нет — это план, по которому строится каркас (этап 0).

## 1. Что строим

Анонимные голосовые комнаты для знакомства студентов. Одно приложение на iOS, Android и в браузере, один общий код.

Главный принцип: **анонимно для собеседников, но не для модерации.** Собеседники видят только ник. Связь «ник ↔ аккаунт» знает только сервер и показывает её только админам, с записью в журнал.

## 2. Схема

```
  iPhone / Android / браузер
  (одно приложение: Expo + React Native + TypeScript)
        │                  │                    │
        │ HTTPS (REST)     │ WebSocket          │ WebRTC (звук)
        ▼                  ▼                    ▼
  ┌─────────────────────────────┐        ┌──────────────┐
  │  Наш сервер (API)           │──────► │   LiveKit    │
  │  Node.js + TypeScript       │ команды│ (голос, наш  │
  │  вход, расписание, комнаты, │ «выгнать»│ сервер, без │
  │  голосования, мэтчи, чат    │ «заглушить»│ записи)   │
  └──────┬───────────┬──────────┘        └──────────────┘
         │           │
         ▼           ▼
   PostgreSQL      Redis            Отдельно: админка (веб),
   (всё, что       (кто сейчас      почта для кодов входа,
   хранится)       в комнате,       push-уведомления,
                   голосования)     сбор ошибок
```

Всё, что на схеме ниже приложения, размещается на российском хостинге.

## 3. Части системы

| Часть | Технология | Зачем |
|---|---|---|
| Приложение | Expo (React Native) + TypeScript, Expo Router | Один код для iOS, Android и веба |
| Сервер API | Node.js + TypeScript, Fastify | Вся логика: вход, комнаты, голосования, мэтчи, чат |
| База данных | PostgreSQL + Drizzle ORM | Постоянное хранение |
| Быстрая память | Redis | Кто в комнате, идущие голосования, ограничения частоты |
| Голос | LiveKit (открытый код, свой сервер) + встроенный TURN | Передача звука. Запись (egress) не устанавливается вообще |
| События в реальном времени | WebSocket на нашем сервере | Голосования, «кого выгнали», чат |
| Push | Expo Push (iOS/Android), Web Push (браузер) | Напоминания за час и за 5 минут |
| Почта | Российский сервис рассылки | Коды для входа |
| Ошибки | GlitchTip на своём сервере (совместим с Sentry SDK) | Доля сессий без падений |
| Метрики | Своя таблица событий в PostgreSQL | Метрики пилота без сторонней аналитики |
| Админка | Отдельная веб-страница (React), вход с 2FA | Жалобы, баны, расписание, метрики |

Конкретный хостинг, почтовый сервис и вопрос push через зарубежные серверы — в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md). Причины выбора — в [DECISIONS.md](DECISIONS.md).

## 4. Структура репозитория

Один репозиторий (монорепозиторий, pnpm workspaces):

```
apps/
  mobile/     приложение (iOS, Android, веб)
  server/     сервер API
  admin/      админка (этап 6)
packages/
  shared/     общие типы и проверки данных (zod) для приложения и сервера
infra/        настройки развёртывания (Docker Compose, LiveKit, nginx)
docs/         эта документация
```

Общие типы в `packages/shared` гарантируют, что приложение и сервер одинаково понимают формат данных.

## 5. Как устроена анонимность

Это самое важное техническое требование: **ник нельзя связать с аккаунтом ни в одном ответе сервера.**

1. В базе две отдельные сущности: **аккаунт** (почта, код приглашения, баны) и **персона** (ник, публичный идентификатор).
2. Связь между ними лежит в отдельной таблице `persona_links`. Читать её может только один модуль сервера — `identity`. Остальной код работает только с идентификатором персоны.
3. Во всех ответах другим пользователям — только `personaId` и ник. Идентификатор аккаунта и почта не выходят наружу никогда.
4. Даже в ответах самому себе данные аккаунта и данные персоны отдаются разными запросами и не смешиваются в одном ответе.
5. В LiveKit участник известен под `personaId`. LiveKit ничего не знает об аккаунтах.
6. Админ может раскрыть связь только через админку, с указанием причины; каждый просмотр пишется в журнал `admin_audit_log`.
7. Автотест проверяет все ответы API: в них не должно быть `accountId` и почты.

Баны и подсчёт «выгнали из 3 комнат» ведутся по аккаунту (внутри сервера), а не по нику — смена ника от бана не спасает.

## 6. Основной сценарий

1. Студент вводит код приглашения и почту → получает код на почту → входит → выбирает ник.
2. Видит расписание. За час и за 5 минут приходит push.
3. Нажимает на push → попадает в комнату (не более 3 нажатий и 5 секунд). Сервер выбирает комнату в слоте; если в ней больше 25 человек — открывает вторую.
4. Сервер выдаёт приложению временный пропуск (токен) LiveKit. Студент входит с выключенным микрофоном, слушает, потом говорит.
5. Модерация — голосованием участников (см. [MODERATION_RULES.md](MODERATION_RULES.md)). Решение исполняет сервер: командует LiveKit отключить микрофон или удалить участника.
6. После комнаты 24 часа можно тайно отметить «хочу пообщаться ещё». При взаимной отметке пара появляется в «Знакомых по комнатам».
7. Ступени раскрытия → чат (или обмен ссылками, если юрист не разрешит свой чат).

## 7. Голос

- LiveKit работает как «ретранслятор» (SFU): каждый отправляет звук один раз на сервер, сервер раздаёт остальным. Это выдерживает 25 человек на слабых телефонах.
- Только звук, видео отключено на уровне прав в токене.
- При обрыве связи приложение переподключается само; цель — не дольше 10 секунд.
- Запись звука невозможна технически: компонент записи LiveKit (egress) не устанавливается.
- На iOS и Android нужна сборка приложения с нативным модулем LiveKit (Expo development build), а не Expo Go.

## 8. Безопасность и данные

- Не собираем ФИО, телефон, фото документов.
- Почта хранится зашифрованной; для поиска при входе — её хэш.
- Сообщения чата удаляются автоматически через 90 дней.
- Невзаимные отметки не показываются никому (в том числе в админке) и удаляются после закрытия окна в 24 часа.
- Все секреты (ключи, пароли) — только в переменных окружения, не в репозитории.
- Нет интеграции с системами КубГУ. Название и логотип КубГУ не используются до разрешения.

## 9. Что не входит в пилот

Посты, новости, группы, объявления, 3D-карта, перевод сообщений, роли преподавателей и абитуриентов, разбор серьёзных случаев (угрозы и т.п.).
