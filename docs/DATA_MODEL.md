# Модель данных

Какие таблицы есть и будут в базе (PostgreSQL). Точное описание созданных таблиц — в `apps/server/src/db/schema/`. Пометки: ✅ создана, ⏳ запланирована.

Таблицы делятся на три группы:

- **Ядро соцсети** (`schema/core.ts`) — аккаунт и роль, вход, приглашения, профиль, фото, уведомления.
- **Модуль «Голосовые комнаты»** (`schema/rooms.ts`) — имена таблиц начинаются с `room`. Знают только анонимную персону.
- **Мост** (`schema/bridge.ts`) — одна таблица, связывающая аккаунт с персоной комнат.

- **Модули соцсети** — посты и истории: свои файлы таблиц, имена с префиксом `post` и `story`. Лента таблиц не имеет.

Будущие модули (друзья, сообщения, группы) получат свои файлы таблиц и свой префикс.

## Три личности

```
   accounts ─────────── profiles            (ядро: закрытый аккаунт и открытый профиль)
      │
      │  persona_links  ← единственный мост, читает только core/identity
      │
   room_personas                             (модуль комнат: анонимный ник)
```

Профиль и персона напрямую не связаны нигде. Чтобы узнать, чей ник, нужен «мост» — а он доступен только одному модулю сервера и админке с журналом.

## Ядро соцсети

### accounts — аккаунт ✅
Закрытая часть: не видна никому, кроме сервера и админов.

| Поле | Что это |
|---|---|
| id | внутренний идентификатор, наружу не выходит |
| email_encrypted | почта в зашифрованном виде. Пусто только у гостя, вошедшего без регистрации |
| email_hash | отпечаток почты для поиска при входе, уникальный. Пусто у гостя без регистрации |
| invite_code_id | каким кодом приглашения воспользовался; пусто, если регистрировался с анкетой или вошёл гостем |
| role | роль: student / teacher / guest. Студент и преподаватель выбирают её сами в анкете (или её задаёт код приглашения); меняет только админ |
| last_name, first_name, patronymic | фамилия, имя, отчество из анкеты регистрации. Наружу не отдаются |
| gender | пол из анкеты студента (male / female). Наружу не отдаётся |
| staff_id | идентификационный номер преподавателя из анкеты. Виден только админам; пока никем не проверяется (вопрос G1) |
| status | active / banned |
| banned_until | до какого времени бан. Бан запрещает публиковать, лайкать, комментировать и входить в комнаты; ставит и снимает админ |
| created_at | когда создан |

### profiles — открытый профиль соцсети ✅
Открытая личность человека. Один профиль на аккаунт. При регистрации с анкетой создаётся сразу (имя и дата рождения из анкеты); при регистрации по коду приглашения — при заполнении. У гостя без регистрации профиля нет.

| Поле | Что это |
|---|---|
| id | публичный идентификатор (`profileId`) — его видят другие пользователи |
| account_id | чей профиль; уникальный, наружу не выходит |
| display_name | имя, как человек себя назвал (обязательно) |
| avatar_media_id | аватар — ссылка на фото в `media_files` |
| faculty, course | факультет и курс (у преподавателя и гостя курса нет) |
| about | о себе |
| username | публичный никнейм (@ivan.petrov): латиница строчными, цифры, точка, подчёркивание, 3–20 знаков; уникальный. В API называется `username`. **К нику комнат отношения не имеет** |
| department | кафедра (только у преподавателя) |
| links | до трёх ссылок (http/https) |
| birth_date | дата рождения; другим видна, только если включено `show_birth` |
| show_faculty, show_birth, show_friends, show_online | «что видно в профиле». Первые два сервер уже соблюдает: скрытое не отдаётся другим. Два последних пока только хранятся (друзей и статуса «в сети» ещё нет) |
| created_at, updated_at | когда создан и изменён |

Роль в профиле показывается, но хранится в аккаунте. Профиль видят все вошедшие пользователи, включая гостей.

### media_files — загруженные фото ✅
Аватары, фото постов и историй.

| Поле | Что это |
|---|---|
| id | идентификатор фото |
| owner_account_id | кто загрузил; наружу не выходит |
| purpose | для чего: аватар, пост или история |
| storage_key | где лежит файл: при разработке — на диске, при запуске — в облачном хранилище |
| width, height, bytes, mime | размеры и тип |
| created_at | когда загружено |

Перед сохранением фото уменьшается и очищается от служебных данных (места съёмки). При удалении поста, истории или аккаунта файл удаляется.

### invite_codes — коды приглашений ✅
id, code, label (пометка для нас), max_uses и used_count, expires_at, created_at. Поле `role` — какую роль получает зарегистрировавшийся по этому коду (студент, преподаватель, гость).

### email_login_codes — одноразовые коды входа ✅
email_hash, code_hash, invite_code_id (если это регистрация по коду приглашения), signup (анкета регистрации, пока почта не подтверждена; удаляется вместе с кодом), deliverable (отправлялось ли письмо), attempts (не больше 5), expires_at (10 минут), created_at. Одна запись на почту.

### sessions — сессии входа ✅
id, token_hash, account_id, expires_at (90 дней; у гостя без регистрации — 30), created_at. Токен — случайная строка, в базе только её отпечаток.

### push_subscriptions — адреса для уведомлений ✅
account_id, kind (пока только `webpush` — браузер), endpoint, p256dh и auth (ключи шифрования), created_at. Наружу не отдаётся. Уведомления — общая служба ядра: ею пользуются комнаты, позже — сообщения и лента.

### admin_audit_log — журнал действий админов ✅
Кто (аккаунт админа — наружу не отдаётся; подпись «Админ 1»), что сделал (удалил пост или комментарий, отклонил жалобу, закрыл жалобу из комнаты, закрыл или открыл вход в комнаты, выдал или снял бан в соцсети), к чему это относится, пояснение, время. Записи не редактируются. Отдельной таблицы админов нет: список — в настройке сервера `ADMIN_EMAILS`.

### events — события для метрик ⏳
Без идентификатора аккаунта и без почты.

## Мост

### persona_links ✅
account_id, persona_id. Одна персона на аккаунт. **Читает только `core/identity`** — это проверяет автотест. Запись создаётся только у студентов и только при первом обращении к комнатам.

## Модуль «Голосовые комнаты»

### room_personas — анонимная персона ✅
То, что видят собеседники в комнате.

| Поле | Что это |
|---|---|
| id | публичный случайный идентификатор (`personaId`) |
| nickname | ник комнат; пустой, пока человек его не выбрал |
| nickname_key | ник в нижнем регистре с «ё»→«е» — для проверки уникальности |
| nickname_changed_at | когда менялся (смена не чаще раза в 30 дней) |
| created_at | когда создана |

### room_slots — расписание ✅
id, title, starts_at (уникальное), duration_minutes, status (scheduled / cancelled), created_at. «Идёт» и «закончилась» вычисляются по времени.

### room_slot_reminders — отправленные напоминания ✅
slot_id, minutes_before (60 или 5), sent_at. Чтобы каждое напоминание ушло ровно один раз.

### rooms — комнаты ✅
id, slot_id, index (1, 2, …), voice_room_name (случайное имя на сервере звука), opened_at, closed_at.

### room_participations — кто был в комнате ✅
room_id, persona_id, joined_at, left_at. Нужна для списка «с кем я был в комнате», метрик и правил голосования. Поля «брал ли слово» добавятся вместе с метриками.

### room_votes, room_vote_ballots — голосования ✅
Тип (выгнать / выключить микрофон), против кого, кто начал, окно, число участников на старте, сколько голосов нужно, итог. Отдельные голоса — в `room_vote_ballots`; наружу не отдаются.

### room_sanctions — решения участников ✅
persona_id, тип (`mute` — выключен микрофон в комнате; `room_block` — выгнали, вход во все комнаты закрыт; `rooms_ban` — автобан), комната, источник (голосование / автоматика / админ), срок. Привязаны к персоне: смена ника не помогает.

### room_personal_mutes — «заглушить для себя» ✅
persona_id, muted_persona_id.

### room_reports — «Сообщить админам» ✅
Кто (персона), на кого, из какой комнаты, текст, статус, когда закрыта. Разбирает админ в админке.

### room_marks — тайные отметки «хочу пообщаться ещё» ⏳
from_persona_id, to_persona_id, room_id, created_at. Не отдаются ни в одном запросе и не показываются в админке; невзаимные удаляются через 24 часа.

### room_matches, room_match_reveals — взаимные мэтчи и открытые ступени ⏳
«Знакомые по комнатам». Каждый открывает свои ступени отдельно.

### room_reveal_cards — что человек показывает на ступенях ⏳
Раньше планировалась отдельная анкета (факультет, курс, интересы; затем имя и ссылка на VK/Telegram). Теперь, когда есть профиль соцсети, возможно, вторая ступень должна открывать сам профиль. Не решено — вопрос F5.

### room_chat_messages — чат после второй ступени ⏳
Удаляются через 90 дней. Под вопросом: если в соцсети будет модуль «Сообщения», отдельный чат комнат может быть не нужен (вопрос F7).

## Модуль «Посты» ✅

Работает с профилем. О комнатах и персоне ничего не знает.

### posts — посты
id, author_profile_id, text, created_at. Удалить может автор.

### post_photos — фото поста
post_id, media_id, position (порядок, от 1 до 10).

### post_likes — лайки
post_id, profile_id, created_at. Один лайк от человека на пост.

### post_comments — комментарии
id, post_id, author_profile_id, text, created_at. Удалить может автор комментария и автор поста.

### post_reports — жалобы
id, reporter_profile_id, target_type (пост или комментарий), target_id, target_author_profile_id (автор записи на момент жалобы), reason, status (новая / закрыта), resolution (запись удалена / жалоба отклонена), resolved_at, created_at. Жалоба сохраняется, даже если саму запись удалили. Разбирает админ в админке.

## Модуль «Истории» ✅

### stories — истории
id, author_profile_id, media_id, caption, created_at, expires_at (через 24 часа). После срока история не отдаётся ни в одном запросе; файл и запись удаляет фоновая задача.

### story_views — кто посмотрел
story_id, viewer_profile_id, viewed_at. Список видит только автор.

## Модуль «Лента» ✅

Своих таблиц нет: лента — это посты всех пользователей по времени, с подгрузкой, и истории за последние 24 часа.

## Будущие модули (таблиц ещё нет)

| Модуль | Что будет хранить | К чему привязано |
|---|---|---|
| Друзья и подписки | заявки и связи между профилями | профиль |
| Сообщения | переписка между профилями | профиль |
| Группы | группы, участники, записи групп | профиль |
| Новости вуза | записи от организаторов | админ |
| Жалобы на записи | кто, на что, статус (вопрос G10) | профиль |

Все модули соцсети работают с **профилем**. С персоной комнат работает только модуль комнат.

## Сроки хранения

| Данные | Срок |
|---|---|
| Невзаимные отметки | до конца 24-часового окна |
| Одноразовые коды входа | 10 минут |
| Истории и их фото | 24 часа |
| Посты, комментарии, лайки, фото | пока автор не удалит их или аккаунт |
| Сообщения чата комнат | 90 дней |
| События метрик | до конца пилота + отчёт (уточнить) |
| Журнал админов | не удаляется на время пилота |
| Аккаунт, профиль, посты, истории, фото, персона | до удаления аккаунта пользователем — удаляется всё сразу |
