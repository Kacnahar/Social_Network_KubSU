# API

Список запросов, которыми приложение общается с сервером. Это черновик договора между приложением и сервером; точные поля фиксируются в коде (`packages/shared`).

## Общие правила

- Адрес: `/v1/...`, формат JSON, только HTTPS.
- Вход: заголовок `Authorization: Bearer <токен сессии>`.
- **Ни один ответ не содержит `accountId` или почту.** Другим пользователям отдаётся только `personaId` и ник. Это проверяется автотестом на все ответы.
- Данные аккаунта (`/v1/account/...`) и данные персоны (`/v1/me/...`) — разные запросы, в одном ответе не смешиваются.
- Ошибки: `{ "error": { "code": "...", "message": "..." } }`.
- Ограничение частоты запросов на вход, голосования, отметки и жалобы.

## Этап 1 — вход и ник

| Запрос | Что делает |
|---|---|
| `POST /v1/auth/start` | Отправляет на почту одноразовый код. Два режима — см. ниже |
| `POST /v1/auth/verify` | Принимает почту и код из письма, выдаёт токен сессии (действует 90 дней) |
| `POST /v1/auth/logout` | Завершает сессию на этом устройстве |
| `GET /v1/account` | Статус аккаунта: активен / забанен и до какого времени. Без ника |
| `DELETE /v1/account` | Удаление аккаунта, ника и всех данных |
| `GET /v1/me` | Своя персона: `personaId`, ник, когда можно сменить ник |
| `PUT /v1/me/nickname` | Задать или сменить ник (не чаще раза в 30 дней) |

Статус: **сделано** (этап 1). Анкета для ступеней раскрытия (`/v1/me/profile`) перенесена на этап 5.

**Два режима `auth/start`:**
- *С кодом приглашения* (регистрация). Неверный, просроченный или исчерпанный код — ошибка `invalid_invite`. Если почта уже зарегистрирована, человек просто входит, приглашение не тратится.
- *Без кода приглашения* (вход). Ответ всегда одинаковый; письмо уходит, только если аккаунт существует. Так нельзя проверить, зарегистрирована ли чужая почта.

**Защита кода из письма:** 6 цифр, действует 10 минут, не больше 5 попыток, повторная отправка не чаще раза в минуту, новый код отменяет старый. Приглашение тратится в момент подтверждения кода, а не запроса.

**Ник:** от 3 до 20 символов — русские и латинские буквы, цифры, «_». Уникальность без учёта регистра и буквы «ё». Служебные имена (admin, модератор и т.п.) отвечают как занятые.

**Режим разработки:** пока не подключена отправка писем, `auth/start` возвращает код в поле `devCode`. В продакшене это запрещено настройками — сервер не запустится.

Коды ошибок: `validation_error`, `invalid_invite`, `invalid_code`, `too_many_requests`, `unauthorized`, `nickname_invalid`, `nickname_taken`, `nickname_change_too_soon`, `not_found`, `internal_error`.

## Этап 2 — расписание и push

| Запрос | Что делает |
|---|---|
| `GET /v1/slots` | Ближайшие комнаты (до 20): название, время начала, длительность, состояние `upcoming` / `live`. Прошедшие и отменённые не отдаются |
| `GET /v1/push/config` | Открытый ключ для подписки на уведомления (без входа). `null` — напоминания на сервере выключены |
| `POST /v1/push/subscriptions` | Подписать этот браузер на напоминания |
| `DELETE /v1/push/subscriptions` | Отписать этот браузер |

Статус: **сделано** для браузера. Push для приложений на iPhone и Android — позже (нужен аккаунт разработчика Apple).

Напоминания отправляет сервер: за час и за 5 минут до комнаты, по одному разу, всем подписанным и не забаненным. В уведомлении — название комнаты, «начнётся через час / через 5 минут» и ссылка на главный экран; личных данных нет. Адрес подписки принимается только от известных push-сервисов браузеров. Подписка удаляется при выходе, удалении аккаунта и когда браузер её отозвал.

## Этап 3 — голосовые комнаты

| Запрос | Что делает |
|---|---|
| `POST /v1/slots/:slotId/join` | Сервер выбирает комнату (новая — если в текущих по 25 человек) и возвращает `roomId`, адрес сервера звука `voiceUrl`, временный пропуск `voiceToken` и время окончания `endsAt` |
| `POST /v1/rooms/:roomId/leave` | Отметить выход из комнаты |

Статус: **сделано** для браузера. У слота в `GET /v1/slots` появилось поле `joinable` — можно ли войти прямо сейчас.

Сам звук идёт напрямую между приложением и сервером звука (LiveKit). Список участников и «кто говорит» приложение тоже получает от сервера звука — там человек известен только под `personaId` и ником. Отдельного запроса «состояние комнаты» пока нет; он появится вместе с голосованиями (этап 4).

Отказы: `nickname_required` (нет ника), `room_not_open` (ещё закрыта, закончилась или отменена), `account_banned`, `voice_unavailable` (сервер звука недоступен), `not_found`.

## Этап 4 — модерация

| Запрос | Что делает |
|---|---|
| `POST /v1/rooms/:roomId/votes` | Начать голосование: `type` (kick / mute), `targetPersonaId` |
| `POST /v1/votes/:voteId/ballot` | Проголосовать «за» |
| `PUT /v1/me/mutes/:personaId` | Заглушить человека для себя |
| `DELETE /v1/me/mutes/:personaId` | Снять личную заглушку |
| `POST /v1/reports` | «Сообщить админам» |

Правила порогов — в [MODERATION_RULES.md](MODERATION_RULES.md). Кто именно голосовал, в ответах не раскрывается.

## Этап 5 — «ещё раз», раскрытие, чат

| Запрос | Что делает |
|---|---|
| `GET /v1/rooms/recent` | Комнаты за последние 24 часа и с кем в них был — для отметок |
| `PUT /v1/marks` | Поставить тайную отметку: `roomId`, `personaId`. Ответ всегда одинаковый — по нему нельзя понять, взаимно или нет |
| `DELETE /v1/marks` | Снять отметку (пока открыто окно) |
| `GET /v1/matches` | «Знакомые по комнатам» — только взаимные |
| `POST /v1/matches/:matchId/reveal` | Открыть свою ступень 1 или 2 |
| `GET /v1/matches/:matchId` | Что открыто с обеих сторон |
| `GET /v1/matches/:matchId/messages` | Сообщения чата (после второй ступени) |
| `POST /v1/matches/:matchId/messages` | Отправить сообщение |

Важно: взаимный мэтч появляется в списке только **после закрытия 24-часового окна** или с задержкой — иначе по моменту появления можно вычислить, кто кого отметил. Точное правило — в OPEN_QUESTIONS.

## События в реальном времени (WebSocket `/v1/ws`)

Сервер → приложение:

| Событие | Когда |
|---|---|
| `room.participant_joined` / `room.participant_left` | Кто-то вошёл или вышел |
| `vote.started` | Началось голосование |
| `vote.updated` | Изменилось число голосов |
| `vote.finished` | Итог голосования |
| `moderation.muted` | Тебе выключили микрофон |
| `moderation.kicked` | Тебя выгнали |
| `room.closing` | Комната скоро закроется |
| `match.created` | Появился взаимный мэтч |
| `chat.message` | Новое сообщение |

## Этап 6 — админка (`/v1/admin/...`, отдельный вход с 2FA)

| Запрос | Что делает |
|---|---|
| `POST /v1/admin/auth/login` | Вход админа |
| `GET/POST /v1/admin/invite-codes` | Коды приглашений |
| `GET/POST/PATCH /v1/admin/slots` | Расписание |
| `GET/PATCH /v1/admin/reports` | Жалобы |
| `POST /v1/admin/personas/:personaId/resolve` | Раскрыть связь «ник → аккаунт». Обязательна причина, пишется в журнал |
| `POST /v1/admin/accounts/:accountId/ban` / `unban` | Бан и разбан |
| `GET /v1/admin/metrics` | Метрики пилота |
| `GET /v1/admin/audit-log` | Журнал действий админов |

Админские ответы — единственное место, где встречаются данные аккаунта. Невзаимные отметки не отдаются и здесь.
