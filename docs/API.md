# API

Список запросов, которыми приложение общается с сервером. Точные поля — в коде (`packages/shared`). Пометки: ✅ сделано, ⏳ позже.

Запросы делятся на **ядро соцсети** и **модули**. У каждого модуля свой префикс адреса.

| Раздел | Адреса | Состояние |
|---|---|---|
| Ядро: состояние сервера, вход, аккаунт, уведомления | `/v1/health`, `/v1/auth/*`, `/v1/account`, `/v1/push/*` | сделано |
| Ядро: профиль и фото | `/v1/profile`, `/v1/profiles/*`, `/v1/media/*` | часть 1 |
| Модуль «Голосовые комнаты» (только студентам) | `/v1/rooms/*` | сделано для браузера |
| Модуль «Посты» | `/v1/posts/*` | сделано |
| Модуль «Лента» | `/v1/feed` | сделано |
| Модуль «Истории» | `/v1/stories/*` | сделано |
| Друзья, сообщения, группы, новости | — | позже |
| Админка | `/v1/admin/*` | разбор жалоб — сделано |

## Общие правила

- Формат JSON, только HTTPS. Вход: заголовок `Authorization: Bearer <токен сессии>`.
- **Ни один ответ не содержит `accountId` или почту.**
- **Модуль комнат отдаёт только `personaId` и ник комнат. Ядро и остальные модули никогда не отдают `personaId` и ник комнат.** Данные профиля и персоны не встречаются в одном ответе — даже в ответе самому пользователю.
- Ошибки: `{ "error": { "code": "...", "message": "..." } }`, текст — по-русски, готовый для показа.
- Ограничение частоты запросов, более строгое на вход.

## Роли и отказы

Сервер проверяет роль в каждом запросе. Скрытая в приложении кнопка — не защита.

| Запросы | Студент | Преподаватель | Гость |
|---|---|---|---|
| Чтение: лента, профили, посты, комментарии, истории | да | да | да |
| Свой профиль: создать, изменить, загрузить аватар | да | да | да |
| Посты, комментарии, лайки, истории: создать, удалить своё | да | да | **отказ** |
| Загрузка фото для постов и историй | да | да | **отказ** |
| Всё под `/v1/rooms` | да | **отказ** | **отказ** |

Отказ — ответ 403 с кодом `forbidden`. На каждую ячейку «отказ» есть автотест.

## Путь «вошёл → нажал кнопку → в комнате»

```
Один раз:
  POST /v1/auth/start            код приглашения + почта → письмо с кодом
  POST /v1/auth/verify           код из письма → токен сессии
  PUT  /v1/profile               заполнить профиль                     (человек в соцсети)
  PUT  /v1/rooms/me/nickname     студент — при первом входе в «Войс»: ник комнат

Каждый раз:
  GET  /v1/rooms/slots           какие комнаты открыты (поле joinable)
  POST /v1/rooms/slots/:id/join  нажал кнопку → адрес сервера звука и пропуск
  …приложение подключается к серверу звука — человек в комнате
  POST /v1/rooms/:roomId/leave   вышел
```

При нажатии кнопки ничего вводить и подтверждать не нужно: сервер по токену сам понимает, кто это, и сам находит его анонимную персону.

## Ядро

### Вход ✅

| Запрос | Что делает |
|---|---|
| `POST /v1/auth/start` | Отправляет на почту одноразовый код. Два режима — см. ниже |
| `POST /v1/auth/verify` | Принимает почту и код из письма, выдаёт токен сессии (90 дней) |
| `POST /v1/auth/logout` | Завершает сессию на этом устройстве |

**Два режима `auth/start`:**
- *С кодом приглашения* (регистрация). Неверный, просроченный или исчерпанный код — ошибка `invalid_invite`. Если почта уже зарегистрирована, человек просто входит, приглашение не тратится.
- *Без кода приглашения* (вход). Ответ всегда одинаковый; письмо уходит, только если аккаунт существует — так нельзя проверить, зарегистрирована ли чужая почта.

**Защита кода из письма:** 6 цифр, 10 минут, не больше 5 попыток, повторная отправка не чаще раза в минуту, новый код отменяет старый. Приглашение тратится при подтверждении кода.

**Режим разработки:** пока нет отправки писем, `auth/start` возвращает код в поле `devCode`. В продакшене это запрещено настройками.

### Аккаунт ✅

| Запрос | Что делает |
|---|---|
| `GET /v1/account` | Статус: активен / забанен и до какого времени |
| `DELETE /v1/account` | Удаление аккаунта и всего связанного, включая персону комнат |

### Уведомления ✅ (браузер)

| Запрос | Что делает |
|---|---|
| `GET /v1/push/config` | Открытый ключ для подписки (без входа). `null` — уведомления выключены |
| `POST /v1/push/subscriptions` | Подписать этот браузер |
| `DELETE /v1/push/subscriptions` | Отписать этот браузер |

Уведомления — общая служба: сейчас ею пользуются напоминания о комнатах, позже — сообщения и лента. В тексте уведомления нет личных данных. Адрес подписки принимается только от известных push-сервисов браузеров.

### Роль ✅

`GET /v1/account` дополнительно отдаёт `role` (student / teacher / guest) — по ней приложение решает, какие кнопки показывать.

### Профиль соцсети ✅

| Запрос | Что делает |
|---|---|
| `GET /v1/profile` | Свой профиль: `{ profile }`; `null`, если ещё не заполнен — приложение ведёт на экран заполнения |
| `PUT /v1/profile` | Создать или изменить свой профиль: имя, факультет, курс, «о себе», аватар |
| `GET /v1/profiles/:profileId` | Чужой профиль: имя, аватар, факультет, курс, «о себе», роль |

В ответах профиля никогда нет `personaId` и ника комнат.

### Фото ✅

| Запрос | Что делает |
|---|---|
| `POST /v1/media?purpose=avatar` | Загрузить фото: тело запроса — сами байты картинки. Сервер проверяет, что это картинка, уменьшает, стирает служебные данные и возвращает идентификатор. `purpose` — `avatar`, `post` или `story`; гостю разрешён только `avatar` |
| `GET /v1/media/:mediaId` | Получить фото. Без входа: адрес содержит случайный идентификатор |

До 10 МБ; JPEG, PNG, WebP. Отказы: `media_invalid`, `media_too_large`.

### GIF ✅

GIF берутся из каталога gifs.ru. Приложение ходит только на наш сервер, а к gifs.ru обращается сам сервер: ключ gifs.ru (`GIFS_RU_API_KEY` в `apps/server/.env`) в приложение, ответы и журнал не попадает.

| Запрос | Что делает | Кому можно |
|---|---|---|
| `GET /v1/gifs/trending?pos=…` | Популярные GIF, по 24 | студент, преподаватель |
| `GET /v1/gifs/search?q=…&pos=…` | Поиск GIF по словам (до 50 знаков, русский и английский), по 24 | студент, преподаватель |

Ответ: `{ gifs: [{ id, previewUrl, url, width, height }], next }`. `id` — идентификатор в gifs.ru; `previewUrl` — маленькая версия (для сетки и комментариев), `url` — полная (для поста); `width`/`height` — для правильных пропорций; `next` передаётся в `?pos=`, чтобы получить следующую порцию (`null` — больше нет).

Ответы запоминаются на сервере: популярные на 10 минут, поиск на час (сейчас — в памяти сервера; Redis в проекте нет, хранилище подменяется через `GifCache`). Не больше 90 запросов в минуту на человека (`GIFS_RATE_LIMIT_PER_MINUTE`), дальше `too_many_requests`. Гостю — `forbidden`. Если gifs.ru не отвечает, превышен их суточный лимит или ключ не задан — `gifs_unavailable` (503); приложение показывает «GIF сейчас недоступны».

Выбранный GIF прикрепляется к посту или комментарию целиком этим же объектом (поле `gif`). Сервер хранит идентификатор, адреса и размеры, сам файл не хранит; адреса принимаются только с серверов gifs.ru.

## Модуль «Посты» — `/v1/posts` ✅

| Запрос | Что делает | Кому можно |
|---|---|---|
| `POST /v1/posts` | Опубликовать пост: текст (до 5000 знаков) и до 10 фото, загруженных через `POST /v1/media?purpose=post`, либо один GIF (`gif`, без фото) | студент, преподаватель |
| `GET /v1/posts/:postId` | Один пост | все вошедшие |
| `DELETE /v1/posts/:postId` | Удалить свой пост вместе с фото, лайками и комментариями | автор |
| `GET /v1/profiles/:profileId/posts?before=…` | Посты человека, новые сверху, по 20 | все вошедшие |
| `PUT/DELETE /v1/posts/:postId/like` | Поставить или убрать лайк | студент, преподаватель |
| `GET /v1/posts/:postId/comments?after=…` | Комментарии, от старых к новым, по 50 | все вошедшие |
| `POST /v1/posts/:postId/comments` | Написать комментарий: текст (до 1000 знаков) и/или один GIF (`gif`) | студент, преподаватель |
| `DELETE /v1/posts/comments/:commentId` | Удалить комментарий | автор комментария или автор поста |
| `POST /v1/posts/:postId/report`, `POST /v1/posts/comments/:commentId/report` | Пожаловаться | все вошедшие, включая гостя |

В ответе о посте: автор (профиль: идентификатор, имя, аватар, роль), текст, фото с размерами, GIF (`gif` или `null`), число лайков, поставил ли лайк я, число комментариев, время, могу ли я удалить. Чтобы публиковать, лайкать и комментировать, нужен заполненный профиль — иначе отказ `profile_required`.

## Модуль «Лента» — `/v1/feed` ✅

| Запрос | Что делает |
|---|---|
| `GET /v1/feed?before=…` | Посты всех пользователей, новые сверху, по 20; `before` — откуда продолжать при прокрутке. Доступно всем ролям |

К каждому посту: автор (профиль), текст, фото, число лайков, поставил ли лайк я, число комментариев. Друзья и подписки — позже, пока лента общая.

## Модуль «Истории» — `/v1/stories` ✅

| Запрос | Что делает | Кому можно |
|---|---|---|
| `GET /v1/stories` | Истории за последние 24 часа, собранные по авторам — для кружков вверху ленты. У каждой: фото, подпись, когда исчезнет, посмотрел ли я | все вошедшие |
| `POST /v1/stories` | Выложить историю: фото (загруженное через `POST /v1/media?purpose=story`) и подпись до 200 знаков | студент, преподаватель |
| `POST /v1/stories/:storyId/view` | Отметить просмотр | все, у кого есть профиль |

| `DELETE /v1/stories/:storyId` | Удалить свою историю вместе с фото | автор |

История старше 24 часов не отдаётся ни одним запросом. Число просмотров в списке видно только автору.

## Модуль «Голосовые комнаты» — `/v1/rooms`

Доступен только студентам: преподаватель и гость получают отказ `forbidden` на каждом запросе этого раздела. Анонимная персона создаётся при первом обращении студента к комнатам.

### Персона ✅

| Запрос | Что делает |
|---|---|
| `GET /v1/rooms/me` | Своя анонимная персона: `personaId`, ник, когда можно сменить ник |
| `PUT /v1/rooms/me/nickname` | Задать или сменить ник комнат (не чаще раза в 30 дней) |

Ник: от 3 до 20 символов — русские и латинские буквы, цифры, «_». Уникальность без учёта регистра и буквы «ё». Служебные имена отвечают как занятые.

### Расписание и вход ✅ (браузер)

| Запрос | Что делает |
|---|---|
| `GET /v1/rooms/slots` | Ближайшие комнаты (до 20): название, время, длительность, `state` (`upcoming` / `live`), `joinable` — можно ли войти сейчас |
| `POST /v1/rooms/slots/:slotId/join` | Сервер выбирает комнату (новая — если в текущих по 25 человек) и возвращает `roomId`, `voiceUrl`, `voiceToken`, `endsAt` |
| `POST /v1/rooms/:roomId/leave` | Отметить выход |

Войти можно за 5 минут до начала и до конца. Сам звук идёт напрямую между приложением и сервером звука; там человек известен только под `personaId` и ником. Напоминания сервер шлёт за час и за 5 минут до комнаты.

Отказы: `nickname_required`, `room_not_open`, `account_banned`, `voice_unavailable`, `not_found`.

### Модерация ✅ (браузер)

| Запрос | Что делает |
|---|---|
| `GET /v1/rooms/:roomId/state` | Состояние комнаты для экрана: идущее голосование (тип, против кого, счёт, сколько нужно, когда закончится, голосовал ли я), итог последнего, до какого времени мне выключен микрофон, закрыт ли мне вход, кого я заглушил для себя. Экран опрашивает раз в 2,5 секунды |
| `POST /v1/rooms/:roomId/votes` | Начать голосование: `kick` (выгнать) или `mute` (выключить микрофон). Начавший сразу голосует «за» |
| `POST /v1/rooms/votes/:voteId/ballot` | Проголосовать «за» |
| `PUT/DELETE /v1/rooms/me/mutes/:personaId` | Заглушить человека для себя / вернуть звук |
| `POST /v1/rooms/reports` | «Сообщить админам» |

Пороги и сроки — в [MODERATION_RULES.md](MODERATION_RULES.md). Решение исполняет сервер через сервер звука: запрещает говорить или отключает человека. Кто голосовал, не раскрывается. Отказы: `vote_in_progress`, `vote_cooldown`, `vote_not_possible`, `room_blocked` (при входе, если выгнали).

### «Ещё раз» и раскрытие ⏳

| Запрос | Что делает |
|---|---|
| `GET /v1/rooms/recent` | Комнаты за 24 часа и с кем в них был |
| `PUT/DELETE /v1/rooms/marks` | Поставить или снять тайную отметку. Ответ всегда одинаковый |
| `GET /v1/rooms/matches` | «Знакомые по комнатам» — только взаимные |
| `POST /v1/rooms/matches/:matchId/reveal` | Открыть свою ступень |

Что именно открывается на ступенях теперь, когда есть профиль соцсети, — вопрос F5.

### События в реальном времени ⏳

Для голосований понадобится постоянное соединение (WebSocket): началось голосование, изменился счёт, тебя выгнали, комната закрывается.

## Будущие модули ⏳

Друзья и подписки, сообщения, группы, новости вуза. Как и посты с историями, они работают с открытым профилем (`profileId`) и никогда не отдают `personaId` и ник комнат. Порядок и оценки — в [ROADMAP.md](ROADMAP.md).

## Админка — `/v1/admin` ✅ (разбор жалоб)

Доступна только аккаунтам, чья почта есть в настройке сервера `ADMIN_EMAILS`; остальные получают отказ `forbidden`. `GET /v1/account` сообщает `isAdmin` — чтобы приложение показало пункт «Админка».

| Запрос | Что делает |
|---|---|
| `GET /v1/admin/reports/posts?status=new\|closed` | Жалобы на посты и комментарии: причина, кто пожаловался (профиль), сама запись с автором и фото, сколько жалоб на эту запись |
| `POST /v1/admin/reports/posts/:reportId/remove` | Удалить запись; все жалобы на неё закрываются |
| `POST /v1/admin/reports/posts/:reportId/dismiss` | Отклонить жалобу, запись остаётся |
| `PUT /v1/admin/profiles/:profileId/ban` | Бан в соцсети на 1–30 дней: человек не может публиковать, комментировать и лайкать; вход и просмотр остаются |
| `DELETE /v1/admin/profiles/:profileId/ban` | Снять бан досрочно |
| `GET /v1/admin/reports/rooms?status=new\|closed` | Жалобы из комнат: текст, ники, закрыт ли человеку вход |
| `POST /v1/admin/reports/rooms/:reportId/close` | Закрыть жалобу |
| `PUT /v1/admin/rooms/personas/:personaId/ban` | Закрыть вход в комнаты на 1–30 дней; из идущей комнаты человека отключает |
| `DELETE /v1/admin/rooms/personas/:personaId/ban` | Открыть вход: снимает «выгнали», автобан и блокировку админа |
| `GET /v1/admin/log` | Журнал действий админов |

Ответы о записях содержат профили, ответы о комнатах — только ники; вместе они не встречаются. Почта и идентификатор аккаунта не отдаются и здесь.

Забаненный на создание поста, истории, комментария и лайка получает отказ `account_banned`; `GET /v1/account` показывает ему `status: banned` и срок.

**Позже:** 2FA, коды приглашений с ролью, смена роли, расписание, метрики. Раскрытие связи «ник комнат → аккаунт/профиль» — только с причиной и записью в журнал; пока не сделано. Невзаимные отметки не отдаются и здесь.

## Коды ошибок

`validation_error`, `invalid_invite`, `invalid_code`, `too_many_requests`, `unauthorized`, `nickname_invalid`, `nickname_taken`, `nickname_change_too_soon`, `nickname_required`, `room_not_open`, `account_banned`, `voice_unavailable`, `push_unavailable`, `not_found`, `internal_error`. `forbidden` (роль не позволяет), `profile_required` (сначала заполните профиль), `media_invalid`, `media_too_large`, `gifs_unavailable` (каталог GIF сейчас недоступен).
